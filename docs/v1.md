# V1 — 掛襟シャツ

Scope for the first version. `docs/app-vision.md` is where the whole thing is going; this is the slice that gets built first.

**The rule: cut features, never depth.** V1 covers one garment, one fabric, one screen — but the engine underneath it is the real engine. The pipeline, the curve handling, the stitch model, the derived materials, the validation: all of it is built properly, because all of it is needed by 掛襟シャツ alone. Adding garments afterwards is writing data, not writing code.

Nothing in V1 is a placeholder to be replaced later.

---

# The garment

掛襟シャツ, as specified in `docs/brief.md`. A band-collar shirt derived from 甚平: rectangular panels, straight tube sleeves, underarm venting, centre-front buttons, no 衽, no overlap.

Its 型 needs:

| Part | Shape |
|---|---|
| 後ろ身頃 | Rectangle, cut on the fold, with a shallow back neck curve |
| 前身頃 ×2 | Rectangle below, diagonal above, joined by a rounded 剣先 |
| そで ×2 | Rectangle |
| 掛襟 | Long straight strip, shaped by pressing |
| まち ×2 | Square, set on the diagonal |

Three curves: the back neck scoop, the rounded 剣先, and the small hem corner. That is enough to require the real curve machinery — arc-length matching for the band against the front edge, and seam-allowance offsetting around the 剣先.

# What V1 does

## 採寸

The measurements this garment needs, entered directly, with a body diagram alongside. Opens on a working default so there is never a blank form.

胸囲 · 身丈 · 裄 · 肩幅 · 首回り

## 意匠

Every design control the garment has, live:

| Control | Range |
|---|---|
| 剣先 depth | 12–25 cm |
| 掛襟 width | 3–8 cm |
| 袖付け opening | 0–10 cm |
| 脇 vent length | 0–25 cm |
| 身八つ口 | on / off |
| Sleeve length | short – long |
| Button count and spacing | derived, adjustable |
| Gusset size | 6–10 cm |
| Hem finish | 三つ折り / ジグザグ / 袋縫い |
| 千鳥かがり | on / off, thread colour |
| 刺し子 back row | on / off |
| ステッチ | colour, rows, distance from edge |

Each states its tradeoff, drawn from `docs/brief.md` Part 1.

## 生地

One fabric at a time, fully described: width, fibre, shrinkage, price, fray behaviour. The design and the fabric stay separate objects even though V1 only pairs one at a time — that separation is depth, not a feature.

広幅 only (110 / 140 cm).

## The pipeline

Complete, end to end:

```
採寸 → ゆとり → 出来上がり寸法 → 縫い代 → 裁ち切り寸法 → 裁ち方図 → 材料 / 縫い方
```

## Validation

All five classes, live:

1. 寸法 consistency — sleeve edge against armhole, band length against the front edge path
2. 縫い代 sufficiency — derived from the edge finish chosen
3. Fabric fit — does it nest in the length you have
4. Wearability — ease band, hem landing point, cuff reaching the wrist
5. Grain — every piece along the bolt

## Stitching

The full model. This garment uses all four kinds:

- **ほつれどめ** — 三つ折り on hems, cuffs, and vent edges
- **ステッチ** — topstitch along the 掛襟, hems, and vents
- **かんぬき止め** — the four bar tacks at the vent tops, which `docs/brief.md` calls the difference between a garment that vents and one with holes in it
- **手縫い飾り** — 千鳥かがり on the underarm vents, 刺し子 across the back

## The document

寸法表 → 材料 → 裁ち方図 → 縫い方

With the fit read in plain language at the top of 寸法表:

> 胸囲ゆとり +14 cm · 裾は腰骨から 12 cm 下 · 袖口は手首から 3 cm 先

材料 fully derived — fabric length, thread metres, interfacing area, button count and diameter, レース糸 and 刺し子糸 lengths when those options are on.

縫い方 generated from the choices, verb-final headings.

## Persistence

The design encodes into the URL. Refresh keeps your work; a link shares it. No accounts, no database.

## Output

A large-print 寸法表 view. Nothing tiled, nothing to print at 1:1 — you mark 裁ち切り寸法 directly on the cloth.

# What V1 does not do

Features, deferred. None of these are depth cuts.

| Deferred | Why it waits |
|---|---|
| Other garments — 甚平, 浴衣, 作務衣, もんぺ, 袴, 足袋 | Nothing to draft against yet. Each is a data file once the engine exists |
| **Trousers of any kind** | Needs the 股ぐり curve and rise validation, which nothing in this garment exercises |
| 生地棚 and 見比べ | One fabric bought. The model already keeps them separable |
| 反物 layout | 広幅 cloth in hand; narrow-bolt layout is a different nesting problem |
| 出来上がり図 illustration | A whole renderer. The ゆとり readout carries the fit information meanwhile |
| Silhouette overlay | Same reason. Matters much more once trousers exist |
| 作業モード | Additive. The document is readable on a phone without it |
| Measure-a-garment-you-own | Back-solving body from finished measurements is unsolved — see `docs/app-vision.md` Part 9 |
| Garment gallery | One garment needs no picker |
| Registry, contributions, provenance | Nothing to contribute to yet |
| SVG / PDF / tiled export | Not wanted; 寸法表 is the output that gets used |
| Size presets S/M/L/LL | One person, one body. A single sensible default is enough |

# The hard parts

Two, both unavoidable and both real work:

1. **Seam-allowance offsetting around the 剣先.** The front edge turns from vertical to diagonal through a rounded corner, and the allowance has to follow it without self-intersecting. Flatten, offset, resolve. This is the geometry piece, and there is no version of this garment that avoids it.

2. **Arc-length matching for the 掛襟.** The band is a straight strip; the edge it sews to is vertical, then curved, then diagonal. Its length is the arc length of that path, computed, not measured off a drawing. `docs/brief.md` gets this wrong by hand — the band's cut width does not finish at the width it claims, and the 170 cm strip does not fit the stated layout. Both become impossible once the length is derived.

Everything else is arithmetic, SVG, and a form.
